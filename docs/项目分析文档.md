## 项目概述

**Open Scouts** 是一个 **AI 驱动的网络监控平台**，让用户创建自动化的"侦察员"(Scouts)任务，持续搜索网络并在发现相关信息时通知用户。

### 典型应用场景
- 监控附近新开的餐厅
- 追踪 AI 行业新闻动态
- 关注特定领域的新产品发布
- 监控任何需要持续更新的信息

### 项目特点
- ✅ 自然语言配置（无需编写代码）
- ✅ 语义去重（避免重复通知）
- ✅ 分布式架构（可扩展到百万级任务）
- ✅ 实时更新（Supabase Realtime）
- ✅ 多用户隔离（RLS 安全策略）

## 快速理解：核心流程（5步）

Open Scouts 的工作原理可以总结为一个简单的 5 步流程：

```
1️⃣ 用户输入
   "帮我追踪 AI 行业新闻，关注 OpenAI、Anthropic"
        ↓
2️⃣ AI 提取关键词
   → search_queries: [
       "OpenAI latest announcements",
       "Anthropic Claude updates",
       "AI industry news"
     ]
   → frequency: "daily"
   → location: "Global"
        ↓
3️⃣ Firecrawl 爬取数据
   → search() - 搜索网络（返回 URL 列表）
   → scrape() - 抓取完整网页内容
        ↓
4️⃣ AI 分析内容
   → 判断是否是主要信息源（新闻 vs 评论）
   → 验证内容真实性（必须抓取网页确认）
   → 对比历史记录（避免报告旧内容）
        ↓
5️⃣ 去重 + 通知
   → 向量相似度检测（0.85 阈值）
   → 相似度 < 0.85 → 发送邮件 📧
   → 相似度 ≥ 0.85 → 跳过（重复内容）
```

### 数据流转

```
自然语言 → 结构化配置 → 网络数据 → 分析结果 → 用户通知
   (用户)     (AI)      (Firecrawl)   (AI)      (邮件)
```

### 关键技术点

| 步骤 | 技术 | 作用 |
|-----|------|------|
| **用户输入** | 自然语言对话 | 无需编程，用户友好 |
| **AI 提取** | OpenAI GPT-4 | 理解意图，生成搜索策略 |
| **数据爬取** | Firecrawl API | 绕过反爬虫，结构化数据 |
| **内容分析** | AI Agent + Function Calling | 5层过滤，确保相关性 |
| **去重** | 向量 Embedding + 余弦相似度 | 语义级别去重，跨语言 |

**核心价值**：让 AI 成为用户的私人网络侦察员，自动执行"搜索 → 筛选 → 去重 → 通知"的完整闭环。

## 工作原理

### 1. Scout 创建流程

```
用户输入查询 → AI Agent 对话 → 提取以下信息:
  ├─ title: Scout 标题
  ├─ goal: 监控目标
  ├─ description: 详细描述
  ├─ location: 地理位置
  ├─ search_queries: 搜索关键词数组
  └─ frequency: 执行频率 (daily/every_3_days/weekly)
```

**对话示例**:
```
User: "帮我追踪 AI 行业的最新新闻"
AI: "我可以帮你创建一个追踪 AI 新闻的 Scout。你希望多久检查一次？"

User: "每天检查一次"
AI: "好的，我会每天为你搜索。你对哪些公司或话题特别感兴趣？"

User: "特别关注 OpenAI、Anthropic 和 Google"
AI: ✅ "Scout 已配置完成！系统将每天自动搜索并通知你。"
```

### 2. 可扩展的调度架构

系统使用**分布式调度器模式**，可扩展到数千个 Scouts:

```
每分钟执行:
pg_cron → dispatch_due_scouts() 函数
    ↓
查找到期的 Scouts (基于 last_run_at + frequency)
    ↓
为每个 Scout 发起独立的 HTTP POST 请求 (pg_net)
    ↓
  ┌────────┼────────┐
  ↓        ↓        ↓
Edge Fn  Edge Fn  Edge Fn  (并行执行，资源隔离)
```

**关键优势**:
- ✅ 每个 Scout 运行在独立的 Edge Function 实例 (256MB 内存, 400秒超时)
- ✅ 避免单一进程瓶颈
- ✅ 自动失败重试和清理机制

### 3. AI Agent 执行流程

```typescript
步骤 1: 创建执行记录 (scout_executions 表)
    ↓
步骤 2: 获取用户的 Firecrawl API 密钥
    ↓
步骤 3: 检查历史重复内容
    - 查询最近 20 次成功执行
    - 使用 summary_embedding (1536维向量)
    - 计算余弦相似度，避免重复通知
    ↓
步骤 4: 构建 AI Agent 上下文
    - Scout 配置信息
    - 最近 5 次发现的内容
    - 用户位置信息
    ↓
步骤 5: OpenAI 函数调用 (Function Calling)
    Tool: search(query, maxAge)
      → 调用 Firecrawl.search()
      → 返回相关网页列表

    Tool: scrape(url)
      → 调用 Firecrawl.scrape()
      → 提取网页完整内容
    ↓
步骤 6: AI 生成执行总结
    - 一句话概括本次发现
    - 使用 OpenAI text-embedding-3-small 生成向量
    - 存储到 summary_text + summary_embedding
    ↓
步骤 7: 重复检测 (去重算法)
    - 将新总结的向量与历史记录对比
    - 相似度 > 0.85 → 标记为重复，不发送邮件
    - 相似度 < 0.85 → 发送邮件通知
    ↓
步骤 8: 发送邮件 (如果发现新内容)
    - 使用 Resend API
    - 发送到用户认证邮箱
```

### 4. 内容相关性判断机制（五层过滤）

系统如何判断爬取的内容是否是用户真正关心的？这是 Open Scouts 最核心的智能之一。

#### **数据来源：Firecrawl API**

```
Firecrawl API 端点:
├─ https://api.firecrawl.dev/v2/search   (网络搜索)
└─ https://api.firecrawl.dev/v2/scrape   (内容抓取)

数据覆盖范围:
✅ 新闻网站 (TechCrunch, The Verge, Wired 等)
✅ 官方博客 (OpenAI Blog, Google AI Blog 等)
✅ 技术媒体 (Hacker News, Medium 等)
✅ 企业官网、产品文档、学术论文

🚫 自动过滤 14 个社交媒体平台:
   facebook.com, twitter.com, x.com, instagram.com,
   linkedin.com, tiktok.com, youtube.com, reddit.com 等
```

#### **第一层：AI 指令引导（System Prompt）**

系统通过精心设计的提示词教会 AI 区分什么是重要信息：

```typescript
// 核心判断框架
**CRITICAL - Focus on PRIMARY Information:**
Prioritize primary sources (announcements, openings, launches, listings)
over secondary commentary (reviews, opinions, tutorials).

Ask yourself: "What is the NEW thing here?"
- NEW restaurant opening → REPORT IT
- Review of existing restaurant → SKIP IT
- Product launch announcement → REPORT IT
- Tutorial about existing product → SKIP IT

Favor concrete facts (dates, locations, specifics) over subjective commentary.
```

**判断原则**：

| 信息类型 | 优先级 | 示例 |
|---------|--------|------|
| **PRIMARY (应报告)** | 高 | 新产品发布、新店开业、融资公告 |
| **SECONDARY (应跳过)** | 低 | 评论文章、使用教程、观点分析 |

**具体性优先**：
```
✅ 优先级高: "New Italian restaurant Bella Vista opens at 123 Main St on June 15"
   (有名称、地址、日期)

❌ 优先级低: "Some new restaurants are opening in the area soon"
   (模糊、不具体)
```

#### **第二层：历史上下文对比（避免重复）**

在 AI 执行搜索**之前**，系统会告诉它最近已经发现了什么：

```typescript
## Recent Previous Findings
The following results were found in recent executions:

1. OpenAI released GPT-4.5 with improved reasoning (found yesterday)
2. Anthropic announced Claude 3 Opus pricing reduction (found 2 days ago)
3. Google unveiled Gemini Ultra 2.0 at I/O conference (found 3 days ago)

**IMPORTANT**: If your current findings are substantially similar to
any of these recent results, you should:
1. Set taskCompleted to false
2. Set taskStatus to "not_found"
3. Mention that the findings were already reported recently

Only report NEW information that differs meaningfully from these recent findings.
```

**AI 的判断逻辑**：
```
当前搜索结果: "OpenAI releases GPT-4.5"
历史记录: "OpenAI released GPT-4.5..." (found yesterday)
    ↓
AI 判断: 这是已报告的内容，不是新发现
    ↓
返回: { taskCompleted: false, taskStatus: "not_found" }
    ↓
结果: 不发送邮件通知
```

#### **第三层：强制验证机制（防止误报）**

AI **不能仅凭搜索片段**就判断内容相关，必须抓取完整网页验证：

```typescript
**CRITICAL - Verification Requirements:**
- You MUST scrape the actual websites to verify your findings
- Search snippets alone are NOT sufficient
- After searching, ALWAYS scrape the most relevant results (at least 2-3 URLs)
- Only report information you've verified by actually reading the full page content
- Search results can be outdated or misleading
```

**工作流程**：
```
Step 1: 搜索 "AI news"
    → 找到 5 个结果

Step 2: 抓取前 3 个 URL 验证
    → URL1: 完整文章确认是新闻 ✅
    → URL2: 404 错误或旧内容 ❌
    → URL3: 确认是新产品发布 ✅

Step 3: 只报告已验证的内容
    → 最终报告: 2 条已验证的新闻
```

#### **第四层：语义去重（向量相似度）**

即使 AI 认为内容是新的，系统仍会用**数学方法**检测重复：

```typescript
// 1. 生成当前发现的语义向量
const summaryText = "OpenAI launched Sora text-to-video model";
const summaryEmbedding = await openai.embeddings.create({
  model: "text-embedding-3-small",
  input: summaryText
});

// 2. 与最近 20 次执行对比
for (const prevExecution of similarExecutions) {
  const similarity = cosineSimilarity(
    summaryEmbedding,
    prevExecution.summary_embedding
  );

  console.log(`Similarity: ${similarity.toFixed(4)}`);

  if (similarity >= 0.85) {  // 85% 相似度阈值
    isDuplicate = true;
    break;  // 检测到重复，跳过邮件通知
  }
}
```

**实际案例对比**：

| 当前摘要 | 历史摘要 | 相似度 | 判定 |
|---------|---------|--------|------|
| "OpenAI launches Sora text-to-video model" | "OpenAI 发布 Sora 视频生成模型" | **0.92** | 重复 ❌ |
| "OpenAI launches Sora" | "Google releases Gemini 1.5" | **0.35** | 新内容 ✅ |
| "New Italian restaurant opens in Denver" | "New Italian restaurant opening in downtown Denver" | **0.88** | 重复 ❌ |

**跨语言去重优势**：
```
"OpenAI 发布 Sora"
  vs
"OpenAI launches Sora"

相似度: 0.92 → 自动识别为同一新闻（无需人工规则）
```

#### **第五层：用户自定义搜索策略**

用户在创建 Scout 时配置的搜索关键词决定了**搜索方向**：

```typescript
// 示例：用户配置的搜索策略
search_queries: [
  "OpenAI latest news announcements",      // 针对性搜索
  "Anthropic Claude updates AI news",      // 特定公司+产品
  "Google AI Gemini latest developments",  // 具体关键词
  "AI startup funding announcements"       // 细分领域
]
```

**策略对比**：

| 配置 | 搜索范围 | 相关性 |
|-----|---------|--------|
| ❌ "AI news" | 过于宽泛，返回大量无关内容 | 低 |
| ✅ "OpenAI GPT-5 announcement" | 精准定位用户关心的内容 | 高 |
| ✅ "Denver new restaurant opening 2024" | 地域+时间+类型精准匹配 | 高 |

#### **完整判断流程**

```
用户关心: "追踪 AI 行业新闻"
    ↓
配置搜索关键词:
  - "OpenAI latest announcements"
  - "Anthropic Claude updates"
  - "Google AI Gemini news"
    ↓
执行搜索 (时间过滤: 最近24小时)
    ↓
Firecrawl 返回 15 条搜索结果
    ↓
【第一层过滤】过滤黑名单域名
  → 移除 3 条社交媒体链接
  → 剩余 12 条
    ↓
【第二层过滤】AI 判断相关性
  → AI 读取搜索片段
  → 询问: "What is the NEW thing here?"
  → 筛选出 6 条主要信息源
  → 跳过 6 条评论/教程
    ↓
【第三层验证】抓取完整网页
  → 抓取前 3 个 URL
  → URL1: 确认是 OpenAI 官方博客 ✅
  → URL2: 404 错误 ❌
  → URL3: 确认是 TechCrunch 新闻 ✅
  → 已验证内容: 2 条
    ↓
【第四层对比】历史上下文检查
  → AI 对比最近 5 次发现
  → "OpenAI Sora" 昨天已报告 → 跳过 ❌
  → "Google Gemini 1.5" 是新内容 ✅
  → 最终筛选: 1 条新内容
    ↓
【第五层去重】语义向量相似度
  → 生成摘要: "Google announces Gemini 1.5..."
```

#### **时间窗口过滤**

根据 Scout 频率动态调整搜索时间范围：

```typescript
function getMaxAge(frequency) {
  switch (frequency) {
    case "daily":
      return 86400000;      // 1 天 = 86,400,000 毫秒
    case "every_3_days":
      return 259200000;     // 3 天
    case "weekly":
      return 604800000;     // 7 天
  }
}

// 搜索时只查询对应时间范围内的内容
await search({
  query: "AI news",
  tbs: "qdr:d"  // qdr:d (day), qdr:w (week), qdr:m (month)
});
```

**实际效果**：
- 每日监控 → 只搜索最近 **24 小时**的新闻
- 每 3 天 → 只搜索最近 **3 天**的内容
- 每周 → 只搜索最近 **7 天**的内容

这避免了重复搜索旧内容，大幅降低 API 成本。

#### **核心优势总结**

**1. 多层防护，避免误报**
- ❌ 不会因为关键词匹配就盲目报告
- ✅ 需要通过 5 层检测才会通知

**2. 语义理解，跨语言去重**
- 自动识别不同语言的相同内容
- 无需手动编写去重规则

**3. 上下文感知，避免重复**
- AI 知道历史发现，主动避免重复
- 只报告与历史记录差异明显的新内容

**4. 严格验证，确保准确性**
- 不依赖搜索片段（可能过时、误导）
- 必须抓取完整网页验证
- 只报告已验证的信息

**5. 成本优化**
- 时间窗口过滤避免重复搜索
- 黑名单过滤节省无效抓取
- 消息窗口限制节省 80% Token 成本

## 数据库设计

### 核心表结构

#### scouts - Scout 配置表
```sql
CREATE TABLE scouts (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id),  -- 用户隔离
  title TEXT,                              -- Scout 名称
  description TEXT,                        -- 详细描述
  goal TEXT,                               -- 监控目标
  search_queries JSONB DEFAULT '[]',       -- 搜索关键词数组
  location JSONB,                          -- {city, latitude, longitude}
  frequency TEXT,                          -- 'daily'|'every_3_days'|'weekly'
  is_active BOOLEAN DEFAULT false,         -- 启用/禁用
  consecutive_failures INT DEFAULT 0,      -- 连续失败计数（3次自动禁用）
  last_run_at TIMESTAMP WITH TIME ZONE,    -- 上次运行时间
  created_at TIMESTAMP WITH TIME ZONE,
  updated_at TIMESTAMP WITH TIME ZONE
);
```

#### scout_executions - 执行历史表
```sql
CREATE TABLE scout_executions (
  id UUID PRIMARY KEY,
  scout_id UUID REFERENCES scouts(id),
  status TEXT,                             -- 'running'|'completed'|'failed'
  started_at TIMESTAMP WITH TIME ZONE,
  completed_at TIMESTAMP WITH TIME ZONE,
  error_message TEXT,
  results_summary JSONB,                   -- 原始搜索结果
  summary_text TEXT,                       -- AI生成的一句话总结
  summary_embedding vector(1536),          -- 总结的向量表示（用于去重）
  created_at TIMESTAMP WITH TIME ZONE
);

-- 向量索引（加速相似度搜索）
CREATE INDEX idx_scout_executions_summary_embedding
ON scout_executions USING hnsw (summary_embedding vector_cosine_ops);
```

#### scout_execution_steps - 执行步骤日志表
```sql
CREATE TABLE scout_execution_steps (
  id UUID PRIMARY KEY,
  execution_id UUID REFERENCES scout_executions(id),
  step_number INTEGER,
  step_type TEXT,                          -- 'search'|'scrape'|'analyze'|'summarize'
  description TEXT,
  input_data JSONB,                        -- 步骤输入参数
  output_data JSONB,                       -- 步骤输出结果
  status TEXT,                             -- 'running'|'completed'|'failed'
  started_at TIMESTAMP WITH TIME ZONE,
  completed_at TIMESTAMP WITH TIME ZONE,
  error_message TEXT,
  created_at TIMESTAMP WITH TIME ZONE
);
```

#### user_preferences - 用户设置表
```sql
CREATE TABLE user_preferences (
  id UUID PRIMARY KEY,
  user_id UUID UNIQUE REFERENCES auth.users(id),
  location JSONB,                          -- 用户默认位置
  firecrawl_api_key TEXT,                  -- 自动生成的 Firecrawl 密钥
  firecrawl_custom_api_key TEXT,           -- 用户自定义密钥（优先级更高）
  firecrawl_key_status TEXT,               -- 密钥状态追踪
  last_test_email_at TIMESTAMP,            -- 测试邮件限流
  created_at TIMESTAMP WITH TIME ZONE,
  updated_at TIMESTAMP WITH TIME ZONE
);
```

### 安全机制

**Row Level Security (RLS)**: 所有表都启用 RLS，用户只能访问自己的数据

```sql
-- scouts 表的 RLS 策略示例
CREATE POLICY "Users can only access their own scouts"
ON scouts FOR ALL
USING (auth.uid() = user_id);

-- 服务角色可以访问所有数据（用于 Edge Functions）
CREATE POLICY "Service role can access all scouts"
ON scouts FOR ALL
TO service_role
USING (true);
```

### 完整流程演示

#### 第一步：用户创建 Scout

用户在首页输入：

```typescript
// 余弦相似度计算函数
function cosineSimilarity(vecA: number[], vecB: number[]): number {
  let dotProduct = 0;
  let normA = 0;
  let normB = 0;

  for (let i = 0; i < vecA.length; i++) {
    dotProduct += vecA[i] * vecB[i];
    normA += vecA[i] * vecA[i];
    normB += vecB[i] * vecB[i];
  }

  return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
}

// 与历史记录对比
let isDuplicate = false;
for (const prevExecution of recentExecutions) {
  const similarity = cosineSimilarity(
    summaryEmbedding,
    prevExecution.summary_embedding
  );

  console.log(`Similarity: ${similarity.toFixed(3)}`);
  // 示例输出：
  // Similarity with "OpenAI released GPT-4.5...": 0.670
  // Similarity with "Anthropic announced Claude 3...": 0.420

  if (similarity > 0.85) {  // 阈值
    isDuplicate = true;
    break;
  }
}
```
